== *Release 3.3.2.Final* _(November 28th 2025)_

See the https://issues.redhat.com/secure/ReleaseNote.jspa?projectId=12317320&version=12470519[complete list of issues].

=== Kafka compatibility

This release has been built against Kafka Connect 4.1.0 and has been tested with version 4.1.0 of the Kafka brokers.
See the https://kafka.apache.org/documentation/#upgrade[Kafka documentation] for compatibility with other versions of Kafka brokers.


=== Upgrading

Before upgrading any connector, be sure to check the backward-incompatible changes that have been made since the release you were using.

When you decide to upgrade one of these connectors to 3.3.2.Final from any earlier versions,
first check the migration notes for the version you're using.
Gracefully stop the running connector, remove the old plugin files, install the 3.3.2.Final plugin files, and restart the connector using the same configuration.
Upon restart, the 3.3.2.Final connectors will continue where the previous connector left off.
As one might expect, all change events previously written to Kafka by the old connector will not be modified.

If you are using our container images, then please do not forget to pull them fresh from https://quay.io/organization/debezium[Quay.io].

=== Breaking changes

Initial offset position validation in Db2 connector could sometimes produce false negatives.
The validation was disabled and as a by-product the support for `when_needed` snapshot mode was removed.
This is only temporary limitation and the full support is planned soon (https://issues.redhat.com/browse/DBZ-9470[DBZ-9470]).

Hibernate 7.1 has changed default mapping for some datatypes, for example time and timestamp provided nine digit precision instead of six.
Thi means that the schema mapping can change after upgrade (https://issues.redhat.com/browse/DBZ-9481[DBZ-9481]).

Debezium Engine did not set thread context classloader which could complicate integration with projects like SpringBoot.
