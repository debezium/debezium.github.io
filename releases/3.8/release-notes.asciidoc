== *Release 3.8.0.Alpha1* _(November 2nd 2026)_

See the https://github.com/orgs/debezium/projects/5/views/6?filterQuery=status%3AReleased+iteration%3A3.8.0.Alpha1[complete list of issues].

=== Kafka compatibility

This release has been built against Kafka Connect 4.3.1 and has been tested with version 4.3.1 of the Kafka brokers.
See the https://kafka.apache.org/documentation/#upgrade[Kafka documentation] for compatibility with other versions of Kafka brokers.


=== Upgrading

Before upgrading any connector, be sure to check the backward-incompatible changes that have been made since the release you were using.

When you decide to upgrade one of these connectors to 3.8.0.Alpha1 from any earlier versions,
first check the migration notes for the version you're using.
Gracefully stop the running connector, remove the old plugin files, install the 3.8.0.Alpha1 plugin files, and restart the connector using the same configuration.
Upon restart, the 3.8.0.Alpha1 connectors will continue where the previous connector left off.
As one might expect, all change events previously written to Kafka by the old connector will not be modified.

If you are using our container images, then please do not forget to pull them fresh from https://quay.io/organization/debezium[Quay.io].


=== Breaking changes

The MySQL connector now maps REAL columns to FLOAT64 (double precision) instead of FLOAT32 when processing DDL events, preventing silent precision loss and ensuring consistency with snapshot-generated schemas (https://github.com/debezium/dbz/issues/2217[debezium/dbz#2217]).

The Debezium Server Kafka sink removes the redundant `wait.message.delivery.timeout.ms` configuration property and relies solely on the Kafka producer's native `delivery.timeout.ms` to control message delivery timeouts (https://github.com/debezium/dbz/issues/2597[debezium/dbz#2597]).

The PostgreSQL connector now supports `NULL` elements within `ENUM` arrays, preserving individual `NULL` values instead of discarding the entire array or failing event processing.
This change is backward-incompatible because `ENUM` array element schemas become optional (https://github.com/debezium/dbz/issues/2771[debezium/dbz#2771]).

The PostgreSQL connector now correctly handles empty `VARBIT(1)` values, preserving the distinction between empty bit strings, `0`, `1`, and SQL `NULL` instead of silently converting empty values to `NULL` or stopping capture (https://github.com/debezium/dbz/issues/2772[debezium/dbz#2772]).

The Databricks Zerobus sink removes its proprietary event filtering mechanism configured through `debezium.sink.zerobus.filter.*` properties in favor of standard Debezium transformations, predicates, and the `skipped.operations` setting (https://github.com/debezium/dbz/issues/2915[debezium/dbz#2915]).
