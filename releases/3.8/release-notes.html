Release Notes for Debezium 3.8

Series overview Documentation

All notable changes for Debezium releases are documented in this file. Release numbers follow Semantic Versioning.

Table of Contents
  • Release 3.8.0.Alpha1 (November 2nd 2026)

Release 3.8.0.Alpha1 (November 2nd 2026)

See the complete list of issues.

Kafka compatibility

This release has been built against Kafka Connect 4.3.1 and has been tested with version 4.3.1 of the Kafka brokers. See the Kafka documentation for compatibility with other versions of Kafka brokers.

Upgrading

Before upgrading any connector, be sure to check the backward-incompatible changes that have been made since the release you were using.

When you decide to upgrade one of these connectors to 3.8.0.Alpha1 from any earlier versions, first check the migration notes for the version you’re using. Gracefully stop the running connector, remove the old plugin files, install the 3.8.0.Alpha1 plugin files, and restart the connector using the same configuration. Upon restart, the 3.8.0.Alpha1 connectors will continue where the previous connector left off. As one might expect, all change events previously written to Kafka by the old connector will not be modified.

If you are using our container images, then please do not forget to pull them fresh from Quay.io.

Breaking changes

The MySQL connector now maps REAL columns to FLOAT64 (double precision) instead of FLOAT32 when processing DDL events, preventing silent precision loss and ensuring consistency with snapshot-generated schemas (debezium/dbz#2217).

The Debezium Server Kafka sink removes the redundant wait.message.delivery.timeout.ms configuration property and relies solely on the Kafka producer’s native delivery.timeout.ms to control message delivery timeouts (debezium/dbz#2597).

The PostgreSQL connector now supports NULL elements within ENUM arrays, preserving individual NULL values instead of discarding the entire array or failing event processing. This change is backward-incompatible because ENUM array element schemas become optional (debezium/dbz#2771).

The PostgreSQL connector now correctly handles empty VARBIT(1) values, preserving the distinction between empty bit strings, 0, 1, and SQL NULL instead of silently converting empty values to NULL or stopping capture (debezium/dbz#2772).

The Databricks Zerobus sink removes its proprietary event filtering mechanism configured through debezium.sink.zerobus.filter.* properties in favor of standard Debezium transformations, predicates, and the skipped.operations setting (debezium/dbz#2915).
