Release 3.2.7.Final (February 27th 2026)

See the complete list of issues.

Kafka compatibility

This release has been built against Kafka Connect 3.9.1 and has been tested with version 3.9.1 of the Kafka brokers. See the Kafka documentation for compatibility with other versions of Kafka brokers.

Upgrading

Before upgrading any connector, be sure to check the backward-incompatible changes that have been made since the release you were using.

When you decide to upgrade one of these connectors to 3.2.7.Final from any earlier versions, first check the migration notes for the version you’re using. Gracefully stop the running connector, remove the old plugin files, install the 3.2.7.Final plugin files, and restart the connector using the same configuration. Upon restart, the 3.2.7.Final connectors will continue where the previous connector left off. As one might expect, all change events previously written to Kafka by the old connector will not be modified.

If you are using our container images, then please do not forget to pull them fresh from Quay.io.

Breaking changes

There are no breaking changes in this release.

New features

  • Support Oracle 26ai (23.26.x) debezium/dbz#1649

Fixes

There are no fixes in this release.

Other changes

  • Backport informix connector pom changes from 3.3 and 3.4 into 3.2 branch. debezium/dbz#1603

  • Update to com.mchange:c3p0 to 0.12.0 debezium/dbz#1654

Release 3.2.0.Alpha1 (April 29th 2025)

See the complete list of issues.

Kafka compatibility

This release has been built against Kafka Connect 4.0.0 and has been tested with version 4.0.0 of the Kafka brokers. See the Kafka documentation for compatibility with other versions of Kafka brokers.

Upgrading

Before upgrading any connector, be sure to check the backward-incompatible changes that have been made since the release you were using.

When you decide to upgrade one of these connectors to 3.2.0.Alpha1 from any earlier versions, first check the migration notes for the version you’re using. Gracefully stop the running connector, remove the old plugin files, install the 3.2.0.Alpha1 plugin files, and restart the connector using the same configuration. Upon restart, the 3.2.0.Alpha1 connectors will continue where the previous connector left off. As one might expect, all change events previously written to Kafka by the old connector will not be modified.

If you are using our container images, then please do not forget to pull them fresh from Quay.io.

Breaking changes

Oracle connector requires a special configuration when JKS is used for TLS connections. This is now properly documented (DBZ-8788).

Debezium is now built and tested with Kafka 4.0 (DBZ-8875).

When previous version of Debezium IBMi connector missed journal file it resumed reading from the next available. This could lead to silent data loss. The behaviour was changed and now connector throws an error (DBZ-8898).
