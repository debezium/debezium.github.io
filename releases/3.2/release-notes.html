Release 3.2.0.CR1 (June 25th 2025)

See the complete list of issues.

Kafka compatibility

This release has been built against Kafka Connect 4.0.0 and has been tested with version 4.0.0 of the Kafka brokers. See the Kafka documentation for compatibility with other versions of Kafka brokers.

Upgrading

Before upgrading any connector, be sure to check the backward-incompatible changes that have been made since the release you were using.

When you decide to upgrade one of these connectors to 3.2.0.CR1 from any earlier versions, first check the migration notes for the version you’re using. Gracefully stop the running connector, remove the old plugin files, install the 3.2.0.CR1 plugin files, and restart the connector using the same configuration. Upon restart, the 3.2.0.CR1 connectors will continue where the previous connector left off. As one might expect, all change events previously written to Kafka by the old connector will not be modified.

If you are using our container images, then please do not forget to pull them fresh from Quay.io.

Breaking changes

A warning was emitted during validation when connector was missing position in the log. The error was then thrown during streaming phase. This behaviour was changed and the error is thrown already in the validation phase (DBZ-9118).

Fixes

  • SQL Server connector doesn’t properly handle special characters in schema names DBZ-9117

  • The presence of "_" in the ORACLE table name caused the cdc to fail DBZ-9131

Other changes

Breaking changes

Deprecated options were removed from ExtractNewRecordState SMT (DBZ-6068).

Debezium has moved from RHOSS Sonatype infrastructure to Maven Central. Location of snapshot releases has changed (DBZ-9025).

FieldToEmbedding used prefix string in the name of configuration options. This is superfluous so the prefix was removed (DBZ-9056).

TRUNCATE and REPLACE statements were stored in internal schema history. As these statements are not relevant to schema representation they are no longer stored (DBZ-9085).

Breaking changes

Oracle connector requires a special configuration when JKS is used for TLS connections. This is now properly documented (DBZ-8788).

Debezium is now built and tested with Kafka 4.0 (DBZ-8875).

When previous version of Debezium IBMi connector missed journal file it resumed reading from the next available. This could lead to silent data loss. The behaviour was changed and now connector throws an error (DBZ-8898).
