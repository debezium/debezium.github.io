== *Release 3.2.0.CR1* _(June 25th 2025)_

See the https://issues.redhat.com/secure/ReleaseNote.jspa?projectId=12317320&version=12462697[complete list of issues].

=== Kafka compatibility

This release has been built against Kafka Connect 4.0.0 and has been tested with version 4.0.0 of the Kafka brokers.
See the https://kafka.apache.org/documentation/#upgrade[Kafka documentation] for compatibility with other versions of Kafka brokers.


=== Upgrading

Before upgrading any connector, be sure to check the backward-incompatible changes that have been made since the release you were using.

When you decide to upgrade one of these connectors to 3.2.0.CR1 from any earlier versions,
first check the migration notes for the version you're using.
Gracefully stop the running connector, remove the old plugin files, install the 3.2.0.CR1 plugin files, and restart the connector using the same configuration.
Upon restart, the 3.2.0.CR1 connectors will continue where the previous connector left off.
As one might expect, all change events previously written to Kafka by the old connector will not be modified.

If you are using our container images, then please do not forget to pull them fresh from https://quay.io/organization/debezium[Quay.io].


=== Breaking changes

A warning was emitted during validation when connector was missing position in the log.
The error was then thrown during streaming phase.
This behaviour was changed and the error is thrown already in the validation phase (https://issues.redhat.com/browse/DBZ-9118[DBZ-9118]).

=== Breaking changes

Deprecated options were removed from `ExtractNewRecordState` SMT (https://issues.redhat.com/browse/DBZ-6068[DBZ-6068]).

Debezium has moved from RHOSS Sonatype infrastructure to Maven Central.
Location of snapshot releases has changed (https://issues.redhat.com/browse/DBZ-9025[DBZ-9025]).

`FieldToEmbedding` used `prefix` string in the name of configuration options.
This is superfluous so the prefix was removed (https://issues.redhat.com/browse/DBZ-9056[DBZ-9056]).

`TRUNCATE` and `REPLACE` statements were stored in internal schema history.
As these statements are not relevant to schema representation they are no longer stored (https://issues.redhat.com/browse/DBZ-9085[DBZ-9085]).
