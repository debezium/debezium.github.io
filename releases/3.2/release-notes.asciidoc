== *Release 3.2.3.Final* _(September 25th 2025)_

See the https://issues.redhat.com/secure/ReleaseNote.jspa?projectId=12317320&version=12467260[complete list of issues].

=== Kafka compatibility

This release has been built against Kafka Connect 4.0.0 and has been tested with version 4.0.0 of the Kafka brokers.
See the https://kafka.apache.org/documentation/#upgrade[Kafka documentation] for compatibility with other versions of Kafka brokers.


=== Upgrading

Before upgrading any connector, be sure to check the backward-incompatible changes that have been made since the release you were using.

When you decide to upgrade one of these connectors to 3.2.3.Final from any earlier versions,
first check the migration notes for the version you're using.
Gracefully stop the running connector, remove the old plugin files, install the 3.2.3.Final plugin files, and restart the connector using the same configuration.
Upon restart, the 3.2.3.Final connectors will continue where the previous connector left off.
As one might expect, all change events previously written to Kafka by the old connector will not be modified.

If you are using our container images, then please do not forget to pull them fresh from https://quay.io/organization/debezium[Quay.io].


=== Breaking changes

Initial offset position validation in Db2 connector could sometimes produce false negatives.
The validation was disabled and as a by-product the support for `when_needed` snapshot mode was removed.
This is only temporary limitation and the full support is planned soon (https://issues.redhat.com/browse/DBZ-9470[DBZ-9470]).


=== New features

There are no new features in this release.


=== Fixes

This is superfluous so the prefix was removed (https://issues.redhat.com/browse/DBZ-9056[DBZ-9056]).

`TRUNCATE` and `REPLACE` statements were stored in internal schema history.
As these statements are not relevant to schema representation they are no longer stored (https://issues.redhat.com/browse/DBZ-9085[DBZ-9085]).

== *Release 3.2.0.Alpha1* _(April 29th 2025)_

See the https://issues.redhat.com/secure/ReleaseNote.jspa?projectId=12317320&version=12449948[complete list of issues].

=== Kafka compatibility

This release has been built against Kafka Connect 4.0.0 and has been tested with version 4.0.0 of the Kafka brokers.
See the https://kafka.apache.org/documentation/#upgrade[Kafka documentation] for compatibility with other versions of Kafka brokers.


=== Upgrading

Before upgrading any connector, be sure to check the backward-incompatible changes that have been made since the release you were using.

When you decide to upgrade one of these connectors to 3.2.0.Alpha1 from any earlier versions,
first check the migration notes for the version you're using.
Gracefully stop the running connector, remove the old plugin files, install the 3.2.0.Alpha1 plugin files, and restart the connector using the same configuration.
Upon restart, the 3.2.0.Alpha1 connectors will continue where the previous connector left off.
As one might expect, all change events previously written to Kafka by the old connector will not be modified.

If you are using our container images, then please do not forget to pull them fresh from https://quay.io/organization/debezium[Quay.io].


=== Breaking changes

Oracle connector requires a special configuration when JKS is used for TLS connections.
This is now properly documented (https://issues.redhat.com/browse/DBZ-8788[DBZ-8788]).

Debezium is now built and tested with Kafka 4.0 (https://issues.redhat.com/browse/DBZ-8875[DBZ-8875]).

When previous version of Debezium IBMi connector missed journal file it resumed reading from the next available.
This could lead to silent data loss.
The behaviour was changed and now connector throws an error (https://issues.redhat.com/browse/DBZ-8898[DBZ-8898]).
