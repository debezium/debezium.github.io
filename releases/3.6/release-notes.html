Release 3.6.3.Final (September 18th 2026)

See the complete list of issues.

Kafka compatibility

This release has been built against Kafka Connect 4.3.0 and has been tested with version 4.3.0 of the Kafka brokers. See the Kafka documentation for compatibility with other versions of Kafka brokers.

Upgrading

Before upgrading any connector, be sure to check the backward-incompatible changes that have been made since the release you were using.

When you decide to upgrade one of these connectors to 3.6.3.Final from any earlier versions, first check the migration notes for the version you’re using. Gracefully stop the running connector, remove the old plugin files, install the 3.6.3.Final plugin files, and restart the connector using the same configuration. Upon restart, the 3.6.3.Final connectors will continue where the previous connector left off. As one might expect, all change events previously written to Kafka by the old connector will not be modified.

If you are using our container images, then please do not forget to pull them fresh from Quay.io.

Breaking changes

The Oracle connector’s handling of rollbacks to a savepoint has been corrected. Previously, when LOB support was enabled, an UPDATE folded into an INSERT lost its row identifier so the rolled-back change could not be located and was emitted anyway, and a partial rollback mined at the end of a mining session could be re-applied in the next session, dropping a legitimate earlier change. Partial rollbacks are now matched correctly and applied idempotently, so after upgrading, changes rolled back to a savepoint are no longer emitted and changes previously dropped are emitted correctly; no configuration changes are required (debezium/dbz#1422, debezium/dbz#1914).

Users should remove their Ehcache or Infinispan cache files during the upgrade process because the format of the caches have drifted due to this change. No other behavior has changed as a result of this change (debezium/dbz#2652.
