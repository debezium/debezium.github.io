Release 3.6.0.Beta1 (May 29th 2026)

See the complete list of issues.

Kafka compatibility

This release has been built against Kafka Connect 4.3.0 and has been tested with version 4.3.0 of the Kafka brokers. See the Kafka documentation for compatibility with other versions of Kafka brokers.

Upgrading

Before upgrading any connector, be sure to check the backward-incompatible changes that have been made since the release you were using.

When you decide to upgrade one of these connectors to 3.6.0.Beta1 from any earlier versions, first check the migration notes for the version you’re using. Gracefully stop the running connector, remove the old plugin files, install the 3.6.0.Beta1 plugin files, and restart the connector using the same configuration. Upon restart, the 3.6.0.Beta1 connectors will continue where the previous connector left off. As one might expect, all change events previously written to Kafka by the old connector will not be modified.

If you are using our container images, then please do not forget to pull them fresh from Quay.io.

Breaking changes

The Oracle connector’s redo_log_catalog mining strategy has been deprecated and is planned for removal in a future release. Users should migrate to the online_catalog strategy, as maintaining redo_log_catalog introduces significant testing, behavioral, and performance overhead, including increased archive log generation and more complex dictionary management (debezium/dbz#1693).

Release 3.6.0.Alpha1 (April 22nd 2026)

See the complete list of issues.

Kafka compatibility

This release has been built against Kafka Connect 4.1.1 and has been tested with version 4.1.1 of the Kafka brokers. See the Kafka documentation for compatibility with other versions of Kafka brokers.

Upgrading

Before upgrading any connector, be sure to check the backward-incompatible changes that have been made since the release you were using.

When you decide to upgrade one of these connectors to 3.6.0.Alpha1 from any earlier versions, first check the migration notes for the version you’re using. Gracefully stop the running connector, remove the old plugin files, install the 3.6.0.Alpha1 plugin files, and restart the connector using the same configuration. Upon restart, the 3.6.0.Alpha1 connectors will continue where the previous connector left off. As one might expect, all change events previously written to Kafka by the old connector will not be modified.

If you are using our container images, then please do not forget to pull them fresh from Quay.io.

Breaking changes

Order of enum column options in PostgreSQL schema was not defined. This could lead to fake schema change during the processing. The order now follows the logical order as defined in database (debezium/dbz#1331).

MongoDB could not handle collections whose names started with number. This is no longer a problem but the Avro naming conversion is now applied separately for each component of schema name instead of the final schema name (debezium/dbz#305).
