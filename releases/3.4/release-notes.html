Release Notes for Debezium 3.4

All notable changes for Debezium releases are documented in this file. Release numbers follow Semantic Versioning.

Table of Contents
  • Release 3.4.0.Alpha2 (November 5th 2025)
  • Release 3.4.0.Alpha1 (October 23rd 2025)

Release 3.4.0.Alpha2 (November 5th 2025)

See the complete list of issues.

Kafka compatibility

This release has been built against Kafka Connect 4.1.0 and has been tested with version 4.1.0 of the Kafka brokers. See the Kafka documentation for compatibility with other versions of Kafka brokers.

Upgrading

Before upgrading any connector, be sure to check the backward-incompatible changes that have been made since the release you were using.

When you decide to upgrade one of these connectors to 3.4.0.Alpha2 from any earlier versions, first check the migration notes for the version you’re using. Gracefully stop the running connector, remove the old plugin files, install the 3.4.0.Alpha2 plugin files, and restart the connector using the same configuration. Upon restart, the 3.4.0.Alpha2 connectors will continue where the previous connector left off. As one might expect, all change events previously written to Kafka by the old connector will not be modified.

If you are using our container images, then please do not forget to pull them fresh from Quay.io.

Breaking changes

SQL Server used function as default value for data.query.mode. The default mode was changed to direct (DBZ-9394).

Oracle connector now contains xdb and xmlparserv2 in the installation package. It is no longer necessary to install them manually (DBZ-9587).

New features

  • Support for incremental snapshots in IBMi connector DBZ-7958

  • Add metadata to IBMi connector to handle multi-journal DBZ-9291

  • Add support for exclude keyspace from table name flag DBZ-9522

  • Support configuring how to apply dynamic partition routing in Azure Event Hubs sink DBZ-9572

  • Introduce transform to convert between EWKB and WKB formats DBZ-9575

  • Fix failed to initialize open lineage for vitess connector DBZ-9613

  • Expose total time emitting events during commits DBZ-9637

  • The LogMiner commit throughput metric is meaningless DBZ-9639

  • Standardize source catalog descriptions DBZ-9642

  • Debezium Extensions for Quarkus: support for MySQL DBZ-9380

  • Debezium Extensions for Quarkus: support for MariaDB DBZ-9381

  • Debezium Extensions for Quarkus: support for sqlserver DBZ-9384

Fixes

  • Pipeline page Issues DBZ-9543

  • DdlChanges not reset in schema history recovery DBZ-9549

  • Handle exceptions thrown from perfromCommit method to gracefully cleanup the coordinator during the stop call DBZ-9617

  • Table column metadata is not fetched when table name has a '/' character DBZ-9620

  • MySQL connector does not parse CREATE TABLE DBZ-9623

  • Debezium Server run.bat fails to execute on Windows DBZ-9625

  • Begin marker but no end marker for rollbacked transactions DBZ-9628

  • MariaDB fails to parse "CONVERT TO CHARSET <character-set>" DBZ-9634

  • Buffered event count set unnecessarily DBZ-9638

Other changes

  • Enable Dependabot on debezium platform repo DBZ-8994

  • Update Oracle connector doc to specify unsupported Oracle 23ai features DBZ-9402

  • Migrate Surge.sh Preview Teardown from ubuntu-20.04 to ubuntu-latest DBZ-9518

  • Handle the form properties with dot present in their name DBZ-9560

  • Clarify case sensitive nature of signal.data.collection and table names in signals DBZ-9621

  • Remove Technology Preview label on MariaDB list entries in signaling doc DBZ-9624

  • Fix minor issues in the Platform UI dark mode DBZ-9633

  • Update to use only StrimziKafkaCluster DBZ-9640

Release 3.4.0.Alpha1 (October 23rd 2025)

See the complete list of issues.

Kafka compatibility

This release has been built against Kafka Connect 4.1.0 and has been tested with version 4.1.0 of the Kafka brokers. See the Kafka documentation for compatibility with other versions of Kafka brokers.

Upgrading

Before upgrading any connector, be sure to check the backward-incompatible changes that have been made since the release you were using.

When you decide to upgrade one of these connectors to 3.4.0.Alpha1 from any earlier versions, first check the migration notes for the version you’re using. Gracefully stop the running connector, remove the old plugin files, install the 3.4.0.Alpha1 plugin files, and restart the connector using the same configuration. Upon restart, the 3.4.0.Alpha1 connectors will continue where the previous connector left off. As one might expect, all change events previously written to Kafka by the old connector will not be modified.

If you are using our container images, then please do not forget to pull them fresh from Quay.io.

Breaking changes

IBMi connector was automatically trimming both leading and trailing whitespaces from string values. Connector now by default trims leading whitespaces only and the behaviour is controlled by a configuration option (DBZ-8835).

Debezium is no longer tested with PostgreSQL 13 and is not supported by the core team (DBZ-9376).

New features

  • Support Redis Cluster mode in the Debezium Redis sink module DBZ-9226

  • Apply query.fetch.size universally to all Oracle non-snapshot queries DBZ-9448

  • Update documentation to Readonly mode DBZ-9466

  • Apply mining upper boundary to avoid PGA_AGGREGATE_LIMIT DBZ-9476

  • Upgrade Apicurio to version 2.6.13.Final DBZ-9491

  • Add support for SDO_GEOMETRY columns in jdbc-connector DBZ-9508

  • MongoDB docker image with replica set enabled DBZ-9516

  • Use Jakarta variant of ehcache DBZ-9517

  • Add support for PostgreSQL 18 DBZ-9523

  • Support TOKENLIST datatype in Spanner connector DBZ-9526

  • Introduce a Swap Geometry Coordinate System Transform DBZ-9556

  • Enable OpenLineage output dataset events on Debezium Server DBZ-9059

  • Multi-engine Support DBZ-9160

  • Debezium Extensions for Quarkus: support for MongoDB DBZ-9382

  • LogMiner metrics for mining range were added (DBZ-9545).
