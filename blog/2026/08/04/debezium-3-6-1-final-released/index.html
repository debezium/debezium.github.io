Debezium 3.6.1.Final Released Debezium 3.6.1.Final Released
August 4, 2026 by Chris Cranford
releases mongodb mysql mariadb postgres sqlserver cassandra oracle db2 vitess outbox spanner jdbc informix ibmi cockroachdb yashandb ingres

We’re pleased to announce the release of Debezium 3.6.1.Final, a maintenance release that delivers important data integrity and security improvements across multiple connectors.

This release fixes several issues that could affect change event accuracy, including correct parsing of BC-era dates in PostgreSQL, proper mapping of MySQL INTEGER UNSIGNED columns, and resolution of Oracle RowId corruption in change events. The JDBC sink connector also receives a fix for tsvector data handling, and credential leakage has been addressed in log output and configuration serialization.

Debezium Core

Prevent credential leakage in configuration logging

When logging configuration properties, Debezium already masked database passwords but did not cover other sensitive values such as Azure Event Hubs connection strings containing shared access keys.

Configuration logging now masks all credential-bearing properties, preventing accidental exposure in log output. (dbz#27)

Debezium for MySQL

Consistent schema mapping for INTEGER UNSIGNED columns

Columns declared as INTEGER UNSIGNED (a synonym for INT UNSIGNED) were mapped to different schema types during snapshot versus streaming, which could cause schema mismatch errors in downstream consumers.

The connector now consistently maps INTEGER UNSIGNED to INT64 in both modes. (dbz#2172)

Debezium for Oracle

Fix for RowId corruption in change events

The internal encoding used to store Oracle ROWID values was silently truncating part of the identifier, causing the source.row_id field in change events to contain incorrect values for most tables.

The encoding now preserves the full ROWID, ensuring change events accurately reference the originating row. (dbz#2169)

Debezium for PostgreSQL

Correct parsing of BC-era dates

The PostgreSQL connector previously threw a DateTimeParseException when encountering BC-era date values such as 0002-11-30 00:00:00 BC or 0002-11-30 BC. The date parser now correctly handles the BC suffix, allowing these historical date values to be captured without errors. (dbz#1340)

Debezium JDBC sink

Correct tsvector handling for multi-word lexemes

When writing PostgreSQL tsvector values, the JDBC sink was stripping all single quotes from the data before binding. This silently corrupted any tsvector whose lexemes contain spaces or apostrophes — for example, 'new york' would be split into two separate tokens.

The connector now preserves the tsvector value as-is, ensuring lexeme boundaries and content remain intact. (dbz#2199)

Debezium Storage

Mask RocketMQ ACL secret key in configuration output

The RocketMQ storage configuration was rendering its ACL secret key in clear text whenever the configuration was logged or printed.

The secret key is now masked, consistent with how Debezium handles other sensitive values. (dbz#2188)

Other fixes

  • Event count reset for a transaction in progress (dbz#633)

  • Tombstones with JSONB column and table.expand.json.payload produce warning logs (dbz#1369)

  • Snapshot mode no_data incorrectly produces remaining tables JMX metric (dbz#1479)

  • PostgreSQL-to-PostgreSQL type preservation audit exposes several failures (dbz#2100)

  • Make internal.legacy.snapshot.max.threads option public (dbz#2150)

  • ZeroDateFallbackConverter truncates DATETIME(4-6) to millisecond precision (dbz#2187)

  • BIT columns dropped because VitessType does not resolve BIT (dbz#2191)

  • Incremental snapshot silently skipped if the underlying connection is re-opened (dbz#2204)

  • RocketMQ schema history recovery fails on large histories and aborts on corrupted records (dbz#2215)

  • Redis schema history silently drops all records after a corrupted entry during recovery (dbz#2221)

  • Duplicated type name BINARY BINARY emitted for BINARY columns (dbz#2223)

  • Predicates.excludesLiterals returns an includes predicate due to double negation (dbz#2246)

  • DdlNormalizer injects backticks into string literals and SQL comments matching reserved-keyword heuristics (dbz#2254)

  • Oracle secondary configuration should not require secondary.port (dbz#2257)

  • USING INDEX clause in ADD CONSTRAINT fails to parse (dbz#2272)

  • Archive log only mode advances SCN too early (dbz#2296)

In total, 27 issues were resolved in Debezium 3.6.1.Final. The list of changes can also be found in our release notes.

About Debezium

Debezium is an open source distributed platform that turns your existing databases into event streams, so applications can see and respond almost instantly to each committed row-level change in the databases. Debezium is built on top of Kafka and provides Kafka Connect compatible connectors that monitor specific database management systems. Debezium records the history of data changes in Kafka logs, so your application can be stopped and restarted at any time and can easily consume all of the events it missed while it was not running, ensuring that all events are processed correctly and completely. Debezium is open source under the Apache License, Version 2.0.
