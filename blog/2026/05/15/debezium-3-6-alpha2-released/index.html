Debezium 3.6.0.Alpha2 Released Debezium 3.6.0.Alpha2 Released
May 15, 2026 by Chris Cranford
releases mongodb mysql mariadb postgres sqlserver cassandra oracle db2 vitess outbox spanner jdbc informix ibmi cockroachdb

We’re pleased to announce the release of Debezium 3.6.0.Alpha2, the second development preview in the 3.6 series, delivering a range of new features, improvements, and bug fixes. This release introduces quantile metrics across all connectors, JDBC sink support for Debezium Server, and Debezium Platform enhancements including configurable labels and server images. Other highlights include a SQL Server CDC column filter toggle, a Kafka 4.2 upgrade, a Google Cloud BOM update, and the removal of the deprecated MySQL and MariaDB never snapshot mode. Read on for the full details!

Breaking changes

With any new release of software, there can be breaking changes. This release is no exception, so let’s discuss the major changes you should be aware of before upgrading to Debezium 3.6.0.Alpha2.

Debezium for MySQL

Removal of NEVER snapshot mode

The never option has been removed from the snapshot.mode configuration property for MySQL and MariaDB connectors. This mode, which replayed all available binlog events rather than taking an initial snapshot, was deprecated during the Debezium 3.0 release. Users who currently specify snapshot.mode=never will encounter a configuration error at startup and should migrate to one of the remaining valid snapshot modes. (dbz#1832)

Debezium Core

Kafka 4.2.0

Debezium now builds against and supports Apache Kafka 4.2.0. This upgrade brings the latest Kafka client improvements, bug fixes, and protocol enhancements to all Debezium connectors. (dbz#1651)

Quantile metrics

Quantile metrics provide statistical distribution data for metrics such as latencies and other time-based measurements. Originally available only in the Spanner connector, these metrics and their underlying statistics classes have been incorporated into Debezium core, making quantile metrics available across all connectors for more granular performance monitoring and analysis. (dbz#1417)

Debezium for MySQL

Migration to ANTLR Oracle MySQL grammar

The MySQL DDL parser has been migrated from the Positive Technologies MySQL grammar to the ANTLR Oracle MySQL grammar. The Positive Technologies grammar is no longer maintained and is being deprecated by the ANTLR team, making this migration necessary to ensure continued parser updates and compatibility with newer MySQL syntax. (dbz#1216)

If you encounter any issues, you can revert to the legacy DDL parser by setting ddl.parser.type to legacy. The legacy DDL parser will be removed in a future build of Debezium.

Debezium for SQL Server

Internal property to toggle CDC column filters

When CDC is enabled for a SQL Server table with only a subset of columns included in the capture instance, snapshots previously respected the CDC column filter, omitting columns not tracked by CDC. This can cause issues for snapshot-only migrations or when columns are added after CDC was initially enabled.

A new internal configuration property, internal.change.column.filter.override, can be set to true to override this behavior so that all table columns are included during snapshot regardless of the CDC capture configuration. (dbz#1830)

Debezium Platform

Labels for DebeziumServer custom resources

When the Debezium Platform conductor creates a DebeziumServer custom resource for a new pipeline, it now supports passing custom labels to the CR. This enables users to view and manage these resources in tools like ArgoCD that rely on labels for resource discovery and visualization. (dbz#1768)

Configurable Debezium Server image

The Debezium Platform now permits specifying which Debezium Server container image to use when creating a DebeziumServer CRD through a new application property on the conductor. A default value is also configurable via the Helm chart’s values.yaml, providing consistency with how conductor and stage images are already specified. (dbz#1826)

Debezium Server

Google Cloud BOM update to 26.79.0

The Google Cloud Libraries BOM dependency has been updated from 26.17.0 to 26.79.0, bringing improvements in reliability and resilience for cloud-based sinks such as Pub/Sub. This update helps improve network resilience when pushing messages to Google Cloud services. (dbz#1822)

JDBC sink support

The JDBC sink connector, previously available only as a Kafka Connect sink, is now supported as a native Debezium Server sink. This enables lightweight database-to-database replication without requiring a Kafka Connect deployment, supporting all existing JDBC sink capabilities including upsert and insert modes, delete handling, schema evolution, and batch processing across multiple database dialects. (dbz#1842)

About Debezium

Debezium is an open source distributed platform that turns your existing databases into event streams, so applications can see and respond almost instantly to each committed row-level change in the databases. Debezium is built on top of Kafka and provides Kafka Connect compatible connectors that monitor specific database management systems. Debezium records the history of data changes in Kafka logs, so your application can be stopped and restarted at any time and can easily consume all of the events it missed while it was not running, ensuring that all events are processed correctly and completely. Debezium is open source under the Apache License, Version 2.0.
