Tracking Debezium issues on GitHub

Jiri Pechanec
December 1, 2025 · 5 min read
announcement community issues

Introduction

As part of Debezium’s transition to the Commonhaus Foundation, we are also evolving how we track issues and plan work.

Until now, the Debezium project has relied on the Red Hat Jira instance as the primary place to report bugs, request enhancements, and track larger initiatives. Over time, however, our day-to-day development has increasingly centered around GitHub, with pull requests, discussions, and automation already happening there.

To align with this new governance model and simplify the contribution experience, we are moving Debezium issue tracking from Red Hat Jira to GitHub Issues.

What is changing

Starting in December 2025, the Debezium team will use GitHub Issues as the canonical place to track bugs, feature requests, and other work items for the project.

More concretely:

  • New issues will be reported using GitHub Issues in the relevant Debezium repository.

  • The existing Debezium Jira project (DBZ) will be retired and moved to read-only mode.

  • Open issues from Jira will be copied into GitHub Issues so that ongoing work is preserved.

This change does not affect the Debezium code, versioning, or release cadence. It is a process change that brings our issue tracking closer to where contributions already happen.

Migration timeline

To minimize disruption, the migration from Jira to GitHub will happen in stages:

  • December 11th, 2025 – Automatic migration of open Jira issues to GitHub Issues.

  • December 11th – 19th, 2025 – Transition period in which the team will manually move any new Jira issues to GitHub.

  • After December 19th, 2025 – Jira is switched to read-only mode; GitHub Issues becomes the sole system of record.

During the transition window, the Debezium team will actively monitor both Jira and GitHub to make sure that any newly created Jira issues are captured and migrated.

How existing Jira issues will be migrated

To keep the process simple and predictable, we will migrate only the most important parts of each open Jira issue:

  • The issue title will become the GitHub issue title.

  • The issue description will become the GitHub issue body.

  • The component(s) will become the GitHub issue label(s).

  • The Fix version will become the GitHub Project iteration.

Additional Jira metadata such as status, resolution, most of labels and custom fields will not be copied automatically. In practice, this means that:

  • The Debezium team will triage migrated issues in GitHub and add appropriate labels and milestones if necessary.

  • Any follow-up details or clarifications can be added directly as comments on the GitHub issue.

To keep the history of each issue connected across systems, we will:

  • Add a comment to the original Jira issue with a link to the corresponding GitHub issue.

  • Add a comment to the GitHub issue that links back to the original Jira ticket.

This way, you can always navigate between the original Jira context and the new GitHub issue if you need to reference older discussion or attachments.

What you need to do as a user or contributor

For most users, no immediate action is required. However, depending on how you interact with Debezium today, you might want to use GitHub Issues for new reports.

Starting December 11th, 2025, we ask you to fill any new bugs or feature requests directly in GitHub Issues instead of Jira. If necessary please update your documentation and internal links.

If you maintain internal documentation, or wiki pages that point to Jira tickets, you might want to update those references over time to use the new GitHub issues.

If you previously relied on Jira notifications, consider watching the relevant Debezium repositories on GitHub to stay informed about new issues and discussions.

What happens to closed Jira issues?

Closed Jira issues will remain in Jira as historical records. They will not be migrated to GitHub.

You will still be able to browse closed tickets and use them as references while Jira remains accessible in read-only mode. Over time, more and more of the "living" history of Debezium will naturally move to GitHub through new issues and pull requests.

Why this change now?

Moving Debezium to the Commonhaus Foundation gives us an opportunity to revisit some of our long-standing processes and align them with a broader, foundation-driven governance model.

Consolidating issue tracking on GitHub helps us to:

  • Reduce friction for new contributors who are already familiar with GitHub.

  • Keep issues, discussions, and pull requests in a single place.

  • Take advantage of GitHub-native workflows, such as project boards, automation, and cross-repository tracking.

Ultimately, this change should make it easier for you to:

  • Report bugs and ask for new features.

  • Follow the progress of issues that matter to you.

  • Collaborate with the Debezium team and the broader community.

A note of thanks to Red Hat

Before we close, we would also like to express our sincere thanks to Red Hat for hosting the Debezium Jira project for many years. It has been an essential part of how we collaborated with users, tracked bugs, and planned new features. We truly appreciate this long-standing support, which helped Debezium grow from a small experiment into a vibrant open source project.

Looking ahead

The move from Jira to GitHub Issues is one of several steps in Debezium’s transition to the Commonhaus Foundation. As we progress, we will continue to refine our contribution guidelines, governance, and tooling to better support a diverse and growing community.

We appreciate your patience during this transition and welcome your feedback. If you have questions about the migration or run into any problems with issues that were moved from Jira, please let us know through our usual channels:

  • Zulip chat

  • The Debezium Debezium mailing list

On behalf of the Debezium team, thank you for being part of this journey with us. We are excited about what this new chapter at Commonhaus will enable—and we look forward to building it together with you.

About Debezium

Debezium is an open source distributed platform that turns your existing databases into event streams, so applications can see and respond almost instantly to each committed row-level change in the databases. Debezium is built on top of Kafka and provides Kafka Connect compatible connectors that monitor specific database management systems. Debezium records the history of data changes in Kafka logs, so your application can be stopped and restarted at any time and can easily consume all of the events it missed while it was not running, ensuring that all events are processed correctly and completely. Debezium is open source under the Apache License, Version 2.0.

Get involved

We hope you find Debezium interesting and useful, and want to give it a try. Follow us on Twitter @debezium, chat with us on Zulip, or join our mailing list to talk with the community. All of the code is open source on GitHub, so build the code locally and help us improve ours existing connectors and add even more connectors. If you find problems or have ideas how we can improve Debezium, please let us know or log an issue.
