Debezium & AI

Give your models fresh context

Retrieval pipelines and agents are only as current as the data behind them. Debezium turns every committed row change into an event, and can parse, vectorise and deliver it to a vector store without any glue code in between.

One pipeline, no glue code

Each step is a component Debezium ships, configured rather than written.

  1. 1

    Your database

    A row changes. Debezium reads the commit from the transaction log.

  2. 2

    Parse

    The Docling transformation turns documents into clean, chunkable text.

  3. 3

    Embed

    The Embeddings transformation turns that text into vectors in flight.

  4. 4

    Vector store

    Debezium Server writes the result to Qdrant or Milvus.

What Debezium provides

Embeddings in the pipeline

The Embeddings transformation vectorises text as it passes through, using Ollama, Hugging Face, Voyage AI or a local ONNX model.

Documentation

Document parsing

The Docling transformation converts PDF, DOCX and HTML into a form a language model can actually consume.

Documentation

Straight into a vector store

Debezium Server writes to Qdrant and Milvus directly, so the vector index follows the database rather than a nightly job.

Documentation

Native vector columns

Vector column types are captured with their semantics intact, and the Vector to JSON transformation remaps them when you need something plainer.

Documentation

Why drive it from the log

No nightly reindex

Change data capture means only what changed is re-embedded. The cost of keeping an index current tracks your write rate, not the size of your corpus.

The database stays the source of truth

Nothing has to write twice. Your application keeps writing to its database exactly as it does now, and the vector store follows from the log.

Ordering and delivery you can reason about

Events arrive in the order they were committed, and Debezium resumes from where it stopped after a restart - so an index cannot silently drift out of step with the data.
