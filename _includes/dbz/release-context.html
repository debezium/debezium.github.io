{%- comment -%} Resolves the current release picture once, so every section that needs it shares the same answer. Assignments made in a Liquid include stay visible to the including template, so after this line: {% include dbz/release-context.html %} the following are available: dbz_stable_series "3.6" latest stable series dbz_stable_release object its newest release dbz_dev_series "3.7" development series, may be empty dbz_dev_release object its newest release The traversal matches the existing includes: _data/releases directory names are sanitised by Jekyll (the dot is stripped), so series "3.6" is keyed "36", and the newest release in a series is the second-to-last entry of the sorted key list because "series" always sorts last. {%- endcomment -%} {%- for version in site.data.versions.versions -%} {%- assign formatedVersion = version | replace: ".", "" -%} {%- assign releaseDetails = site.data.releases[formatedVersion] -%} {%- if releaseDetails.series.displayed -%} {%- assign sortedReleaseDetails = releaseDetails | sort -%} {%- assign lastIndex = sortedReleaseDetails.size | minus: 2 -%} {%- assign formattedLastVersion = sortedReleaseDetails[lastIndex][0] -%} {%- assign latestRelease = releaseDetails[formattedLastVersion] -%} {%- if latestRelease.stable -%} {%- assign dbz_stable_series = version -%} {%- assign dbz_stable_release = latestRelease -%} {%- assign dbz_stable_overview = releaseDetails.series.overview -%} {%- else -%} {%- assign dbz_dev_series = version -%} {%- assign dbz_dev_release = latestRelease -%} {%- assign dbz_dev_overview = releaseDetails.series.overview -%} {%- endif -%} {%- endif -%} {%- endfor -%}
