{%- comment -%} Most used first. Liquid cannot sort a map by a computed value, so counts are zero padded into sortable "0233|mysql" strings, sorted, then split apart - the same approach as the blog sidebar. {%- endcomment -%} {%- assign tagPairs = "" | split: "," -%} {%- for tag in site.tags -%} {%- assign padded = tag[1].size | prepend: "0000" -%} {%- assign padded = padded | slice: -4, 4 -%} {%- comment -%} Build the pair, then push it. Chaining `push` into `append` does not work: push returns an array, append coerces that array back to a string, and the accumulator stops being a list. {%- endcomment -%} {%- assign pair = padded | append: "|" | append: tag[0] -%} {%- assign tagPairs = tagPairs | push: pair -%} {%- endfor -%} {%- assign topTags = tagPairs | sort | reverse -%}

{%- comment -%} Everything, alphabetically, bucketed by initial letter. Sorting has to be case-insensitive, and Liquid's `sort` is not: it orders by ASCII, so "UI" and "WebAssembly" landed ahead of every lowercase tag and the letter groups came out u, w, a, b, c, ... because group_by_exp preserves the order it is given. So each tag is paired with a lowercased copy of itself, the pairs are sorted on that copy, and the original is recovered afterwards - the same technique used for the count-ordered list above. {%- endcomment -%} {%- assign namePairs = "" | split: "," -%} {%- for tag in site.tags -%} {%- assign pair = tag[0] | downcase | append: "|" | append: tag[0] -%} {%- assign namePairs = namePairs | push: pair -%} {%- endfor -%} {%- assign sortedNames = namePairs | sort -%} {%- assign byLetter = sortedNames | group_by_exp: "p", "p | slice: 0" -%}
