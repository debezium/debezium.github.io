The Debezium project joined the https://commonhaus.org[Commonhaus Foundation] in December 2024.
Over the past year, we've identified a number of variety changes we needed to implement to align with the foundation's policies and to be vendor neutral, like our recent announcement of https://debezium.io/blog/2025/12/01/changing-issue-tracker[moving to GitHub Issues] for issue tracking over Jira.

Another upcoming change focuses on requirements for submitting contributions to the Debezium project.
These changes make sure that Debezium adheres to the Commonhaus Foundation's https://www.commonhaus.org/policies/ip-policy/#contributions[Contributions policy].
In this post, we're going to discuss the upcoming necessary changes so your contributions can continue to be merged, and the expected timeline for these changes.

== History of contributor agreements

In the early days of open source software, it was common for larger projects to require users to sign a https://en.wikipedia.org/wiki/Contributor_License_Agreement[Contributor License Agreement], or more wisely known in the industry as a CLA.
These agreements typically varied by project, but the goal of this agreement was that you are authorized to submit the contribution, and that the project is permitted to use it.
In some instances, like the https://www.apache.org/licenses/icla.pdf[Apache Software Foundation CLA], it may grant copyright and/or patent license use.

In 2004, https://developercertificate.org/[Developer Certificates of Origin] (DCO) were introduced by the Linux Foundation.
Rather than the Contributor License Agreement (CLA) legal contract that must be submitted to projects, this provided a more lightweight mechanism.
The intent remains the same as the CLA, guaranteeing that as the contributor, you have the right to submit the work, and that the project has permission to use it in accordance to its current license provisions.

== How does this apply to Debezium?

The Commonhaus Foundation https://www.commonhaus.org/policies/ip-policy/#contributions[contribution policy] governs how contributions to its projects must be managed.
This policy is flexible, allowing a project to choose which flavor makes the most sense for its community, a CLA vs a DCO.

It's important to clarify that in this context, a contribution does not specifically imply a code change.
If you submit any change to any file in any Debezium repository, that's a contribution, even if you are fixing a small typo in the documentation.

== What does this mean for contributors?

In short, Debezium has chosen to use the DBO process.
This allows for minimal impact to contributors, and aligns with existing git workflows with ease.

The process is quite simple as each commit needs to indicator a sign-off indicator:
[source,text]
----
Signed-off-by: Joe User <joe@debezium-rocks.org>
----

In IDE's like IntelliJ, this available with the click of a small check-box:

If you are using the Git command line, this can be accomplished with an additional toggle on commits:
[source,bash]
----
git commit -m"My Commit Message" --signoff
----

== When does this change take effect?

Beginning in January 2026, Debezium will only accept contributions with signed commits.
This gives the community several weeks to adjust to this new requirement.

We appreciate the contributor community's understanding of this change, which strengthens the security of Debezium's distribution and aligns the project with the Commonhaus Foundation's https://www.commonhaus.org/policies/[policies].
