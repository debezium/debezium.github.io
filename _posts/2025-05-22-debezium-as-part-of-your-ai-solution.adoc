One of the questions we recently encounter is how to effectively integrate change data capture (CDC) with AI workloads — particularly for use cases where organization knowledge is not publicly available.
With the release of Debezium 3.1, new AI-focused features such as the Embeddings SMT and the Milvus Sink make this scenario reality.
You can read more about these enhancements in the https://debezium.io/blog/2025/04/24/debezium-3-1-1-final-released/[Debezium 3.1 release notes].

== Introduction

In this post, we'll show how Debezium, Milvus, and Ollama can work together to form a Retrieval-Augmented Generation (RAG) pipeline.
By capturing changes from a relational database, enriching them with vector embeddings, and enabling similarity search over these vectors, you can build AI-driven applications with up-to-date, domain-specific knowledge.

Let's describe the problem we are aiming to solve.

Our organization introduces new AI-driven application backed by an LLM.
The model needs to be extended with the internal company knowledge that is stored in text documents in PostgreSQL database.
Whenever user interacts with AI the local knowledge must be taken into consideration.
Also the knowledge is constantly changing, new documents are added, existing documents are updated and sometimes some of the documents are withdrawn due to regulatory requirements.

The common solution to this problem is Retrieval-Augmented Generation (RAG).
This post will demostrate how to build CDC fed RAG system using

* PostgreSQL as data storage
* Milvus vector database
* Debezium Server feeding Milvus from PostgreSQL
* Local https://ollama.com/[Ollama] hosted LLM
* Java application interacting with LLM and using RAG to provide prompt context

== What is RAG (Retrieval-Augmented Generation)?

Retrieval-Augmented Generation (RAG) is an AI technique that combines information retrieval with generative models to produce more accurate and contextually relevant responses.
Instead of relying solely on a model's internal knowledge, RAG pipelines retrieve relevant documents or data from an external source (like a vector database) and use that information to enrich the model's responses.
In our scenario, Debezium, Milvus, and Ollama work together to form a RAG workflow: data changes are captured and vectorized, stored in Milvus, and then retrieved to augment LLM outputs with up-to-date, domain-specific information.

== What is Debezium Server?

https://debezium.io/documentation/reference/3.1/operations/debezium-server.html[Debezium Server] is one of Debezium flavours that allows you to stream change events from databases to various sinks without the need to stand up a Kafka cluster.
It provides a lightweight way to consume CDC events and forward them where you need them.
It is also possible to use Kafka Connect single message transformations as a part of its processing pipeline.

== What is Milvus?

Milvus is a specialized vector database designed for similarity search and AI-heavy workloads.
Whether it's product recommendations, image search, or any use case needing fast vector retrieval, Milvus is built for that.
Vector database and fast vector retrieval are in the heart of any RAG solution.
The vector database stores so called *embeddings* - vector representations the data that can be used for tasks like similarity search or clustering.
Prompt context is extended according to similarity of stored data with requested prompt.

=== Why Milvus as a Sink?

For applications where you need up-to-date vector representations of your data, pushing changes from a transactional database into Milvus makes a lot of sense.
This approach keeps your AI models in sync with operational data and offloads similarity search to a system built for it.

=== How Debezium Milvus Sink Works

The typical deployment of Milvus sink can be described with this workflow

* Debezium Connector captures changes from the source database
* If the source database does not contain a field with embedding then https://debezium.io/blog/2025/04/02/debezium-3-1-final-released/#new-features-and-improvements-ai[FieldToEmbedding SMT] is used to enrich change events with vector embeddings
* Milvus sink writes the vector data into Milvus
* Milvus stores and indexes the vectors for fast similarity search

=== Data pipeline

Our source of the documents is https://arxiv.org/[arXiv], service that provides scholarly articles for download in different formats.
The test application downloads requested article based on its identifier and stores it in PostgreSQL table.

The table is created with the following https://github.com/debezium/debezium-examples/blob/main/ai-rag/config-postgres/ai-sample-data.sql[DDL]
[source,sql]
----
CREATE TABLE documents (
  id VARCHAR(64) PRIMARY KEY,
  metadata JSON,
  text TEXT
);
ALTER TABLE documents REPLICA IDENTITY FULL;
----

The table has enabled full replica identity which means that original state of the database row will be available in update and delete messages.
This is not required for our demo but can be useful for different implementations.

Upon user request the application will download the document in text form and store it in the table.
The document identifier will be used as the `id`, the textual representation of the article as `text` and JSON metadata `{"id:" "<document id>"}` in metadata.
There is no column with embeddings so Debezium is responsible for calculation.

We run LLM locally in Ollama LLM framework.
As the model itself we selected https://ollama.com/library/granite3.1-dense:2b[granite3.1-dense:2b], that is text-only model optimized for also for RAG.
It is one of large family of open-source https://huggingface.co/ibm-granite[IBM Granite models] but the application is not limited to it and can use an arbitrary one.

Debezium Server links together PostgreSQL store with Milvus.
As embeddings were not provided, they are calculated using https://github.com/debezium/debezium-examples/blob/main/ai-rag/config-server/application.properties#L16[FieldToEmbedding] SMT and stored in the field named `vector`.

Our application uses LangChain4j Milvus store module internally so we will keep the default collection structure https://github.com/langchain4j/langchain4j/blob/main/langchain4j-milvus/src/main/java/dev/langchain4j/store/embedding/milvus/MilvusEmbeddingStore.java[expected by it]

* `id` - `VarChar`
* `metadata` - `JSON`
* `text` -`VarChar`
* `vector` - `FloatVector`

There is a known https://github.com/langchain4j/langchain4j/issues/2834[issue] in the module that causes application failure when the store is empty.
We are going to store one dummy document in the database (and thus in Milvus) to work around it.

== AI Application

The AI application is the application that interacts with LLM and extends the prompt with data loaded from Milvus stored base on the data and prompt embeddings similarity.

The demo application is a command-line written using https://quarkus.io/[Quarkus framework].
For AI features it uses Quarkus https://docs.quarkiverse.io/quarkus-langchain4j/dev/index.html[LangChain4j extension], specifically https://docs.quarkiverse.io/quarkus-langchain4j/dev/ollama.html[Ollama LLM] and https://docs.quarkiverse.io/quarkus-langchain4j/dev/milvus-store.html[Milvus Store] for RAG.

The AI service is registered via https://github.com/debezium/debezium-examples/blob/main/ai-rag/client/src/main/java/io/debezium/examples/airag/Chat.java[Chat] class.

[source,java]
----
package io.debezium.examples.airag;

import dev.langchain4j.service.SystemMessage;
import dev.langchain4j.service.UserMessage;
import io.quarkiverse.langchain4j.RegisterAiService;

@RegisterAiService(retrievalAugmentor = MilvusRetrieavalAugmentor.class)
public interface Chat {

    @SystemMessage("You are an expert that provides short summaries.")
    String chat(@UserMessage String message);
}
----

The module itself is configured in https://github.com/debezium/debezium-examples/blob/main/ai-rag/client/src/main/resources/application.properties[application.properties].

----
quarkus.langchain4j.ollama.base-url=http://localhost:11434
quarkus.langchain4j.ollama.chat-model.model-id=granite3.1-dense:2b
quarkus.langchain4j.ollama.embedding-model.model-id=granite3.1-dense:2b
quarkus.langchain4j.ollama.timeout=120s
----

RAG is enabled via `retrievalAugmentor` parameter of `@RegisterAiService` and is implemented in https://github.com/debezium/debezium-examples/blob/main/ai-rag/client/src/main/java/io/debezium/examples/airag/MilvusRetrieavalAugmentor.java[MilvusRetrieavalAugmentor] bean.

[source,java]
----
@ApplicationScoped
public class MilvusRetrieavalAugmentor implements Supplier<RetrievalAugmentor> {

    private final RetrievalAugmentor augmentor;

    MilvusRetrieavalAugmentor(MilvusEmbeddingStore store, EmbeddingModel model) {
        EmbeddingStoreContentRetriever contentRetriever = EmbeddingStoreContentRetriever.builder()
                .embeddingModel(model)
                .embeddingStore(store)
                .maxResults(3)
                .build();
        augmentor = new RetrievalAugmentorDecorator(DefaultRetrievalAugmentor
                .builder()
                .contentRetriever(contentRetriever)
                .build());
    }

    @Override
    public RetrievalAugmentor get() {
        return augmentor;
    }

    private class RetrievalAugmentorDecorator implements RetrievalAugmentor {

        private final RetrievalAugmentor delegate;

        public RetrievalAugmentorDecorator(RetrievalAugmentor delegate) {
            this.delegate = delegate;
        }

        @Override
        public AugmentationResult augment(AugmentationRequest augmentationRequest) {
            Log.infof("Requested augmentation of %s", augmentationRequest.chatMessage());
            final var result = delegate.augment(augmentationRequest);
            Log.infof("Result of augmentation is %s", result.contents());
            return result;
        }
    }
}
----

`EmbeddingStoreContentRetriever` is responsible for querying the Milvus vector database and it enhances prompt context with the 3 most similar documents.
The class itself also provides `RetrievalAugmentorDecorator` which logs the detail of augmentation operation.

The Milvus embedding store is again configured in https://github.com/debezium/debezium-examples/blob/main/ai-rag/client/src/main/resources/application.properties[application.properties].

----
quarkus.langchain4j.milvus.host=localhost
quarkus.langchain4j.milvus.port=19530
quarkus.langchain4j.milvus.create-collection=false
quarkus.langchain4j.milvus.collection-name=demo_ai_documents

# These two settings are not supported by the current version of Quarkus Langchain4j extension
# Also field with text cannot be overriden and is default text
quarkus.langchain4j.milvus.primary-field=id
quarkus.langchain4j.milvus.vector-field=vector
----

== Demo

The demo is composed of two components

* Docker Compose configuration https://github.com/debezium/debezium-examples/blob/main/ai-rag/docker-compose.yml[file] that starts all services.
* Java CLI application in https://github.com/debezium/debezium-examples/tree/main/ai-rag/client[client] directory that emulates both data pipeline and AI application.

=== Start deployment

In *Terminal 1* execute command and wait for the containers to start.

----
$ docker-compose up --build
----

The command will extend standard Debezium Server image with `debezium-ai-embeddings-ollama` module (the AI embeddings modules are not by default included).
PostgreSQL (`postgres`), Milvus (`milvus`), Debezium Server (`debezium-server`) and ollama (`ollama`) containers are started.

In *Terminal 2* execute command

----
$ docker exec -it ollama ollama run granite3.1-dense:2b
----

to start Granite LLM model.
We need to make sure that we are testing the application with fact that model is unaware of.
First we will check what is model's cut off date (what are the latest data that model seen).

----
>>> What is your cut off date?
My knowledge cut off date is April 2024. I can provide information and answer questions based on data up to 
that point. For more recent events or discoveries, I'm unable to include those details in my responses as 
they weren't available at the time of my training data. If you have any questions within this timeframe, 
feel free to ask!
----

Based on that fact we selected paper https://arxiv.org/abs/2504.05309v1[2504.05309v1] (IterQR: An Iterative Framework for LLM-based Query Rewrite in e-Commercial Search System) as the sample of the new knowledge.
It was published in February 2025 so after cut off date and contains very specific keyword - `IterQR`.
We will test the model by asking about the framework.

----
>>> Describe IterQR framework in 20 words.
Iterative Quantized Ridge Regression (IterQR), a scalable method for large-scale regression, iteratively 
refines coefficients via quantization and ridge regression techniques to minimize computational complexity 
while maintaining accuracy.
----

The answer is completely unrelated to the framework and exhibits traits of https://en.wikipedia.org/wiki/Hallucination_(artificial_intelligence)[hallucination].
The model does not know about the fact so it invents its own without any connection to reality.
When model is asked multiple times it will provide different and unrelated descriptions.

== Conclusion

This blogpost explains how Debezium 3.1 can be integrated into AI workflows, particularly those using Retrieval-Augmented Generation (RAG).
Debezium captures real-time changes in databases and feeds them into vector databases.
These updates are essential for keeping AI systems current with fresh, domain-specific data.
The example setup involves PostgreSQL, Debezium Server, Milvus, and Granite LLM (with embeddings).
This architecture enables intelligent applications that respond with accurate, up-to-date information.
