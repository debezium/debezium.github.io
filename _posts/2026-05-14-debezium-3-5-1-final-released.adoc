We're pleased to announce the release of *Debezium 3.5.1.Final*, a maintenance release focused on stability, compatibility, and performance improvements across the Debezium platform.

This release brings Informix JDBC driver v15 support, resolves a Debezium Server startup failure, fixes incorrect bytecode generation in the CockroachDB connector, and improves handling of PostgreSQL infinity timestamps in nanosecond precision mode.
Additionally, incremental snapshot handling is now more robust when dealing with invalid snapshot parameters.

Let's take a closer look at the changes included in this release.

=== Debezium Core

==== More robust incremental snapshot error handling

When an incremental snapshot was triggered with invalid parameters, such as an incorrect surrogate key column, the connector could enter a stuck state where snapshot metadata was persisted to offsets but never cleared.
The `stop-snapshot` signal was ineffective in this scenario, leaving users no option but to manually edit offsets or perform a full connector reset.

Incremental snapshot initialization failures now properly avoid persisting invalid metadata, and the `stop-snapshot` signal reliably clears snapshot state, making recovery straightforward without manual intervention.
(https://github.com/debezium/dbz/issues/1533[dbz#1533])

[id="new-features-and-improvements-debezium-postgresql"]
=== Debezium for PostgreSQL

==== Correct handling of infinity timestamps in nanosecond precision mode

When using `time.precision.mode=nanoseconds`, PostgreSQL `infinity` and `-infinity` timestamp values could overflow and produce negative `NanoTimestamp` values, leading to incorrect data in downstream consumers.
The connector now properly handles these special timestamp values in nanosecond precision mode, ensuring that infinity timestamps are correctly represented without overflow.
(https://github.com/debezium/dbz/issues/1833[dbz#1833])

[id="new-features-and-improvements-debezium-server"]
=== Debezium Server

==== Stack overflow startup failure resolved

A stack overflow startup failure has been resolved in Debezium Server when supplying configuration with invalid values.
One example that would cause this would be a typo in the connector class name, leading to repeated `ClassNotFoundException` exceptions.
This issue affected Debezium Server 3.5 deployments and prevented the server from starting entirely.

This fix ensures that should there be any startup exceptions due to configuration mistakes, the process reports the error and stops rather than attempting to restart until a stack overflow occurs.
(https://github.com/debezium/dbz/issues/1779[dbz#1779])

[id="new-features-and-improvements-debezium-cockroachdb"]
=== Debezium for CockroachDB

==== Schema caching for improved throughput

The changefeed event processing pipeline now caches parsed Kafka Connect `Schema` objects per table and reuses them across events when the table schema has not changed.
Benchmarks showed the full parsing pipeline previously cost 3-4x raw JSON deserialization due to rebuilding `Schema` and `Struct` objects on every event.
With schema caching, the common case sees significantly reduced processing overhead, improving overall connector throughput.
(https://github.com/debezium/dbz/issues/1712[dbz#1712])

[id="new-features-and-improvements-debezium-informix"]
=== Debezium for Informix

==== Support for JDBC driver v15

The Informix connector now supports the Informix JDBC driver v15, which is the official driver for Informix 15 and 14.
Previously, the connector only supported JDBC driver v4.50.x, limiting access to new features available in Informix 15.
This upgrade ensures compatibility with the latest Informix platform while maintaining support for existing deployments.
(https://github.com/debezium/dbz/issues/1622[dbz#1622])
