We're pleased to announce the release of **Debezium 3.6.1.Final**, a maintenance release that delivers important data integrity and security improvements across multiple connectors.

This release fixes several issues that could affect change event accuracy, including correct parsing of BC-era dates in PostgreSQL, proper mapping of MySQL INTEGER UNSIGNED columns, and resolution of Oracle RowId corruption in change events.
The JDBC sink connector also receives a fix for tsvector data handling, and credential leakage has been addressed in log output and configuration serialization.

Read on for the full details!

=== Debezium Core

==== Prevent credential leakage in configuration logging

When logging configuration properties, Debezium already masked database passwords but did not cover other sensitive values such as Azure Event Hubs connection strings containing shared access keys.

Configuration logging now masks all credential-bearing properties, preventing accidental exposure in log output.
(https://github.com/debezium/dbz/issues/27[dbz#27])

[id="new-features-and-improvements-debezium-mysql"]
=== Debezium for MySQL

==== Consistent schema mapping for INTEGER UNSIGNED columns

Columns declared as `INTEGER UNSIGNED` (a synonym for `INT UNSIGNED`) were mapped to different schema types during snapshot versus streaming, which could cause schema mismatch errors in downstream consumers.

The connector now consistently maps `INTEGER UNSIGNED` to `INT64` in both modes.
(https://github.com/debezium/dbz/issues/2172[dbz#2172])

[id="new-features-and-improvements-debezium-oracle"]
=== Debezium for Oracle

==== Fix for RowId corruption in change events

The internal encoding used to store Oracle ROWID values was silently truncating part of the identifier, causing the `source.row_id` field in change events to contain incorrect values for most tables.

The encoding now preserves the full ROWID, ensuring change events accurately reference the originating row.
(https://github.com/debezium/dbz/issues/2169[dbz#2169])

[id="new-features-and-improvements-debezium-postgresql"]
=== Debezium for PostgreSQL

==== Correct parsing of BC-era dates

The PostgreSQL connector previously threw a `DateTimeParseException` when encountering BC-era date values such as `0002-11-30 00:00:00 BC` or `0002-11-30 BC`.
The date parser now correctly handles the `BC` suffix, allowing these historical date values to be captured without errors.
(https://github.com/debezium/dbz/issues/1340[dbz#1340])

[id="new-features-and-improvements-debezium-jdbc"]
=== Debezium JDBC sink

==== Correct tsvector handling for multi-word lexemes

When writing PostgreSQL `tsvector` values, the JDBC sink was stripping all single quotes from the data before binding.
This silently corrupted any tsvector whose lexemes contain spaces or apostrophes — for example, `'new york'` would be split into two separate tokens.

The connector now preserves the tsvector value as-is, ensuring lexeme boundaries and content remain intact.
(https://github.com/debezium/dbz/issues/2199[dbz#2199])

[id="new-features-and-improvements-debezium-storage"]
=== Debezium Storage

==== Mask RocketMQ ACL secret key in configuration output

The RocketMQ storage configuration was rendering its ACL secret key in clear text whenever the configuration was logged or printed.

The secret key is now masked, consistent with how Debezium handles other sensitive values.
(https://github.com/debezium/dbz/issues/2188[dbz#2188])
