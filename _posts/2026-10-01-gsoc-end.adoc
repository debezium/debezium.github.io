The Google Summer of Code 2026 program has officially concluded for Debezium, and we are delighted to announce that all our contributors successfully passed their final evaluations! 🎉

Over the past few months, our contributors have worked closely with their mentors and the wider community to design, implement, test, and document new capabilities across the Debezium ecosystem.

Their work was not simply an academic exercise or a collection of experimental prototypes. These contributions address real use cases and are already valuable to the many companies and developers who rely on Debezium. The results are included in Debezium 3.7, which was recently released.

Before looking at what comes next, let’s take a moment to celebrate the contributors and the projects they delivered.

== The GSoC 2026 projects

This year’s projects explored different areas of the Debezium ecosystem, including developer tooling, deployment, artificial intelligence, vector databases, and new data sources. Each project presented its own technical challenges and created new opportunities for the community.

=== Debezium CLI

**Contributor**: https://github.com/Binayak490-cyber[Binayak Das] +
**Mentors**: https://github.com/kmos[Giovanni Panice], https://github.com/mfvitale[Mario Fiore Vitale] +
**Related links**: https://github.com/debezium/debezium-design-documents/pull/46[Debezium Design Document] +

Binayak built a JBang-based CLI (`debezium@debezium`) to streamline the creation, deployment, and management of CDC pipelines. The **build subsystem** scaffolds projects, validates configurations, produces trimmed Debezium Server distributions, and creates OCI container images via Jib Core with registry publishing support. The **platform subsystem** provides multi-environment profile management, connector discovery, live database schema introspection, pipeline signal dispatch, real-time log streaming, and full CRUD operations for connections and transforms.

The Debezium CLI is included in Debezium 3.7, with additional commands and integrations planned for future releases.

=== Host-Based Pipeline Deployment for the Debezium Platform

**Contributor**: https://github.com/d1vyanshu-kumar[Divyanshu Kumar] +
**Mentors**: https://github.com/mfvitale[Mario Fiore Vitale], https://github.com/kmos[Giovanni Panice] +
**Related links**: https://github.com/debezium/debezium-design-documents/pull/45[Debezium Design Document] +

Divyanshu extended the Debezium Platform Conductor to deploy CDC pipelines on bare-metal servers, VMs, and cloud instances — not just Kubernetes. He implemented two complementary runtime strategies: **Ansible mode**, which provisions hosts via playbooks handling SSH discovery and Docker installation, and **Agent mode**, a lightweight Quarkus HTTP server that runs on each target host and manages Docker containers secured with bearer token authentication. The implementation includes pessimistic host locking, dynamic port allocation, and background polling for container lifecycle management.

The work is included in Debezium 3.7, with potential future support for additional provisioning tools and enhanced monitoring.

=== PyDebeziumAI

**Contributor**: https://github.com/KMohnishM[Kodukulla Mohnish Mythreya] +
**Mentors**: https://github.com/jpechane[Jiri Pechanec], https://github.com/vjuranek[Vojtěch Juránek] +
**Related links**: https://github.com/debezium/debezium-design-documents/pull/47[Debezium Design Document] +

Mohnish built a Python library that bridges Debezium’s CDC capabilities with the AI ecosystem, enabling sub-second synchronization of vector store embeddings as source data changes. The library ingests events from an embedded Debezium Engine (via `pydbzengine`), transforms them into LangChain Document objects, and synchronizes them to vector stores (Chroma, PGVector, Milvus) with atomic upserts, soft deletes, and a dead-letter queue. It also includes LangChain-compatible retrievers, LangGraph node integrations, and a Streamlit-based live CDC console.

PyDebeziumAI is included in Debezium 3.7 and published with full documentation on https://debezium-ai-python.readthedocs.io/[ReadTheDocs].

=== Debezium Source Connector for Milvus

**Contributor**: https://github.com/kartikangiras[Kartik Angiras] +
**Mentors**: https://github.com/naros[Chris Cranford], https://github.com/kmos[Giovanni Panice] +
**Related links**: https://github.com/debezium/debezium-design-documents/pull/48[Debezium Design Document] +

Kartik implemented the first CDC source connector for a vector database in the Debezium ecosystem. The connector reads directly from https://milvus.io[Milvus]'s internal message queue physical channel (pchannel), requiring Milvus 2.5+ with a Kafka backend. It provides a consistent initial snapshot anchored to an etcd checkpoint and uses a timetick ordering engine for strict TSO-ordered streaming. The connector auto-detects the wire format, maps FloatVector values to a dedicated logical type, supports collection filtering with regex, and exposes JMX metrics. 

A complete (https://github.com/debezium/debezium-examples/tree/main/milvus-to-pgvector)[Milvus-to-PostgreSQL/pgvector] example demonstrates the full pipeline.

The Milvus connector was first released in Debezium 3.7 as incubating, with potential future support for additional MQ backends and update event handling.

=== Debezium Source Connector for SQLite

**Contributor**: https://github.com/siddhantcvdi[Siddhant Chaturvedi] +
**Mentors**: https://github.com/vsantonastaso[Vincenzo Santonastaso], https://github.com/kmos[Giovanni Panice] +
**Related links**: https://github.com/debezium/debezium-design-documents/pull/49[Debezium Design Document] +

Siddhant implemented an incubating source connector for https://sqlite.org[SQLite] using a trigger-based CDC approach. The connector installs `AFTER INSERT/UPDATE/DELETE` triggers on monitored tables, writing change events to an append-only `_debezium_cdc_log` table — requiring no native extensions, only standard JDBC. It enforces WAL mode for concurrent access, supports multiple snapshot modes, and provides at-least-once delivery with clean resume after restart. Schema change detection via `PRAGMA schema_version` automatically rebuilds triggers on DDL changes. The connector handles all five SQLite storage classes and includes automatic CDC log compaction.

A complete (https://github.com/debezium/debezium-examples/tree/main/tutorial#using-sqlite)[SQLite] example demonstrates the connector capabilities.

The SQLite connector was first released in Debezium 3.7 as incubating, with potential future support for additional SQLite databases like Turso.

== More than a summer project

Although the GSoC program has formally ended, we do not see this milestone as the end of our contributors’ journey with Debezium.

During the program, they became part of the Debezium community. They participated in technical discussions, collaborated with maintainers, received feedback, and contributed capabilities that will be used in real-world environments.

We warmly encourage all our GSoC contributors to remain involved, continue improving their projects, review issues and pull requests, and bring new ideas to the community. Open source contributions do not have to stop when a formal program ends. GSoC introduced the contributors to the project, but the relationships and collaborations built during these months can continue well beyond it.

== What's next

Each contributor prepared a dedicated blog post describing their project.
The posts will be published during October, and they should cover the original motivation, the technical approach and the final results.

We also invited the contributors to demonstrate their projects during the Debezium Weekly Forum.

These sessions will give the community an opportunity to:

- See the new capabilities in action
- Learn about the technical decisions behind each project
- Ask questions directly to the contributors
- Provide feedback based on real-world requirements
- Explore possible future improvements and contributions

In November 2026, we will conclude this journey with a final showcase bringing together all the GSoC projects.

More details about the presentations and the final showcase will be shared through the official Debezium channels.
