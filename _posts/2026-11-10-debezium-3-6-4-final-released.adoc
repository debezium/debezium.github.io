We're pleased to announce **Debezium 3.6.4.Final**, the latest maintenance release of the 3.6 series, focused on stability and reliability.

This release is led by a round of fixes for the Oracle connector, resolving several cases where change events could be missed, most notably on Oracle RAC.
Oracle deployments that capture many tables also benefit from a faster LogMiner query.
Beyond Oracle, the release brings security updates through newer MySQL and MongoDB drivers, including a MySQL driver that addresses a published CVE.

Read on for the full details!

=== Debezium for MongoDB

==== MongoDB driver upgraded to 5.14

The MongoDB connector now ships with version 5.14.0 of the MongoDB Java driver, up from 5.9.2.
The upgrade keeps the connector current with the driver's latest fixes and requires no configuration changes.
(https://github.com/debezium/dbz/issues/3022[dbz#3022])

[id="new-features-and-improvements-debezium-mysql"]
=== Debezium for MySQL

==== MySQL Connector/J upgraded to 26.10.0

The MySQL driver that ships with the MySQL connector and the JDBC sink has been upgraded from 9.1.0 to 26.10.0.
The previous version was affected by CVE-2025-30706, and the newest 9.x driver carries several more recent CVEs, so the upgrade moves directly to the 26.x line.

Most deployments need no changes, but there are two things worth knowing.
Starting with 26.7.0, the driver's release notes list MySQL Server 8.4 and later as supported.
MySQL 8.0 is no longer in that documented range, although the driver does not reject it and the connector's tests continue to pass against it.

The driver also now requires SSL keystores to be local files.
The connector's own SSL settings already work this way, so this only matters if you pass custom `+driver.*+` properties that point at a remote keystore URL.
(https://github.com/debezium/dbz/issues/3015[dbz#3015])

[id="new-features-and-improvements-debezium-oracle"]
=== Debezium for Oracle

==== Faster LogMiner query when capturing many tables

The query that the Oracle connector uses to read changes from LogMiner now handles schema and table lookups more efficiently, which reduces CPU overhead on the database and streams results faster.
The benefit grows with the number of captured tables, so connectors with only a handful of tables will see little difference, while those capturing hundreds of tables gain the most.

The improvement applies when `log.mining.query.filter.mode` is set to `in`.
The same rows are matched as before, and no configuration changes are required.
(https://github.com/debezium/dbz/issues/2991[dbz#2991])
